# Lecture Module Skeleton — LOCKED STANDARD (all weeks)

_Locked 2026-05-30. Every weekly lecture is built from modules, and **every module carries the same eight beats, in this order.** This is the course's pedagogical contract for lectures: it guarantees each concept is introduced, justified, executed, evaluated, grounded in real data, and connected — never floating._

## The eight beats (in order)

1. **What it is** — a one-line definition of the concept/step.
2. **Why we do it** — the purpose/motivation; the question it answers.
3. **How it's done** — the method or mechanics, in plain language.
4. **What we get** — the concrete output the step produces.
5. **Why it matters** — its significance; what would go wrong without it.
6. **In the data** — at least one concrete Book6 instance (numbers, a root, a retrieval). Never a module without a real-data anchor.
7. **Takeaway** — one sentence of synthesis the member should remember.
8. **Bridge** — how it connects to the next module (or, for the last module, the next week).

## Rules

- **All eight beats appear in every teaching module.** Framing modules (opening, wrap) adapt beats 3–6 but still carry a takeaway, a real-data anchor, and a bridge.
- **Beat 6 is non-negotiable.** Even conceptual modules must touch real Book6 numbers, so no idea is taught in the abstract.
- **Beat 7 is one sentence**, quotable, and survives out of context.
- **Beat 8 is forward-looking** and names the next module/week by its concept, creating a single through-line across the lecture.
- **Fact vs. interpretation discipline still applies inside the beats:** computed facts in beats 4/6; any reading is labeled interpretation.
- **Scope discipline still applies:** a module teaches only its week's concept; forward references are allowed only as explicit "bridge"/"preview," never as taught content (e.g., Week 1 may *name* the vector-space model as a preview but does not *teach* embeddings/skip-gram).

## Authoring order (per the Week 1→2 handoff)

Agree the module list + minute markers **before** writing prose → write the lecture notes first (all eight beats per module) → get sign-off → then generate dependents (instructor script, slides, exercise, quiz) so they inherit the same framing. Verify once per batch (Arabic `w:cs` sweep, scope grep, PDF render).
